# 网页日志

浏览器分别保存主板日志和 BambuBus 日志，按收到的 UTF-8 原始字节计量，容量为 1 MiB（1,048,576 字节）和 2 MiB（2,097,152 字节）。两路使用循环槽位，超限淘汰最早完整行；索引另设每路 65,536 条记录的上限，防止大量极短行造成元数据增长。容量不包含时间换算后的文本、索引和 DOM 开销。

第一次进入日志页开始统一轮询，此后切换功能页仍继续收集。日志只保存在当前网页内存中，刷新或关闭网页后释放；筛选设置仍保存在 localStorage。浏览器挂起、网络断开或写入速度超过拉取速度时，设备中已覆盖的内容无法恢复，设备会返回日志缺口提示。

## 显示与操作

- 日志卡片按视口高度扣除页头和页面留白，两路日志框自动填充分配给它们的剩余空间。主板控制项少时扩大，总线筛选项多时缩小；页头换行、升级提示和窗口尺寸变化时自动调整。日志框最低为 180px，短窗口中允许页面滚动以保留控制栏和阅读区。
- 两路都使用虚拟滚动，只为可视区及少量预留行创建节点；向上滚动可查看环形缓冲内的历史。行高按窗口宽度估算，显示时测量并校正，保留长报文换行。
- 新行只解析一次类型和时间；保留类型颜色及筛选，筛选仅影响显示，不丢弃缓存。
- 向上翻阅时保持当前位置；回到底部继续跟随。缓存淘汰了正在阅读的记录时，转到当前最早记录。
- 暂停只冻结显示，仍接收日志；继续后按当前阅读位置或跟随状态显示仍在缓存中的内容。
- 清空会清理当前通道的浏览器缓存，并在下一次统一请求中清空对应设备缓冲。请求代次阻止清空前的响应重新填回该通道。
- 下载导出当前通道的全部完整记录，保留类型字段，不受筛选和可视区限制；已经淘汰的日志无法导出。
- 抓取 30 秒复用同一轮询及总线环形缓存，按点击开始时的筛选条件和设备游标/时间截取；到期先排空截止边界之前的积压再下载。中途重启、断线、设备覆盖或浏览器缓存淘汰会在文件和提示中标明不完整。清空总线日志会取消抓取。
- 设备重启保留浏览器历史，新增启动分界；尾行不会跨启动周期拼接，已经入库的时间不会重新换算。

## 认证请求诊断

`0x040D`（设备证书请求）和 `0x040E`（设备授权请求）有独立总线类型 14、15，网页可分别筛选。固件仅识别和记录，不生成证书或签名应答。

每个通过帧长、CRC8 和 CRC16 校验的 `04/05` 长帧认证请求，在主循环中额外写入主板日志：先记录命令、源/目标地址、序号、总长度、载荷长度和标志，再分行转储完整原始帧。主板记录不受总线日志开关影响；发往其他地址的请求同样记录，并标为 `result=IGNORED`，不会更新本机通信或业务状态。本机请求标为 `result=LOG_ONLY`。

坏 CRC、非请求回显、超过 1000 字节的帧以及进入主循环前已被接收队列丢弃的帧，不会产生有效认证请求记录。因此没有主板记录仍不能证明物理总线上从未出现认证数据；排查时应同时保存 `bus_rx_errors`、`bus_rx_dropped` 和从注册开始的连续日志。

## 合并接口

`GET /api/log?both=1&main_seq=0&bus_seq=0`

可选 `boot` 携带上次响应的启动标识；与设备标识不符时，从本次启动的起点读取两路日志。可选 `clear_mask` 为清空位图：1 主板、2 总线、3 两路；指定通道先清空并同步游标，再返回新内容。

响应为 `application/octet-stream`，主板字节块在前，总线字节块在后，不插入分隔符或 NUL。每路每次最多 8192 字节，设备复用原有 16 KiB 加 64 字节的 HTTP 缓冲，不扩大设备日志缓存。

| 响应头 | 含义 |
|---|---|
| `X-Log-Boot` | 本次启动标识 |
| `X-Uptime-Ms` | 本次读取的设备开机毫秒数 |
| `X-Log-Main-Length` / `X-Log-Bus-Length` | 两个字节块的精确长度 |
| `X-Log-Main-Seq` / `X-Log-Bus-Seq` | 两路读取结束游标 |
| `X-Log-Main-Total` / `X-Log-Bus-Total` | 两路设备写入游标，用于判断积压 |
| `X-Log-Main-Dropped` / `X-Log-Bus-Dropped` | 本次读取前已覆盖或清空的字节数 |
| `X-Log-Boundary` | 本次读取前的总线写入位置，用于抓取起止边界 |

前端先验证 HTTP 状态、响应头和总长度，再按两路长度拆分原始字节。字节按换行组装完整行后才解码 UTF-8，避免中文跨请求截断；未完成单行的缓存限制为 16 KiB，超长行会丢弃并提示。普通无积压轮询间隔 800ms，抓取期间为 200ms；有积压时为 20ms。始终仅允许一个日志请求在途，失败时保留游标并重试。旧的 `ch` / `seq` / `clear` 单通道接口仍保留。

## 验证

```powershell
node tools/tests/test_web_logs.cjs
python -B tools/tests/test_log_bus.py --zig C:/path/to/zig.exe
pio run -e esp32c3
```

网页测试使用真实页面、模拟设备响应和 Edge 无头浏览器，覆盖中文跨响应、失败重试、暂停与切页、清空竞态、重启、抓取范围与筛选快照、双环覆盖、滚动索引、下载及手机换行。每路累计写入 89,600 行，覆盖多轮字节容量并跨过 65,536 个物理槽位，检查显示节点数和垃圾回收后的堆内存。

可设置 `WEB_LOG_SCREENSHOT` 保存手机布局截图；`WEB_LOG_BASELINE` 可指向旧版 HTML，对比真实旧渲染函数、关闭颜色、去掉筛选判断及当前虚拟渲染。比较使用相同 1000px 窗口、相同日志框宽度和约 256 KiB 的日志文本；中位数与高分位数仅代表本机合成数据测试，不是实机连续运行保证。

2026-10-29 本机验证：两路容量稳定，满缓存持续追加时总线约 22 个显示节点，渲染中位数约 0.5–0.6ms；追加 19,200 行并再次回收后，堆内存约从 10.53MB 到 10.58MB。同数据重复渲染的旧实现中位数约 17ms，关闭颜色约 15.1ms、去掉筛选判断约 14.9ms；当前实现约 0.1ms、43 个节点。主要收益来自减少历史文本处理和 DOM 重建，颜色和筛选均保留。

后端测试编译真实 `log_bus.cpp` 的环形缓冲部分及 `handle_log()`，检查二进制/中文、两路分块、独立游标、缺口计数、清空、启动标识和旧接口。它替换 HTTP、时钟及锁边界，不验证 WiFi 时延、ISR 并发或实际硬件通信；没有烧录或进行实机连续打印测试。
