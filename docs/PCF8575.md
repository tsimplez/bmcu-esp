# 四片 PCF8575 扩展 IO

固件在同一条 I2C 总线上支持最多 4 片 PCF8575，共 64 个扩展引脚。地址固定分配如下，每片的引脚名称均为 P0～P7、P10～P17。

| 芯片地址 | 配置中的虚拟引脚编号 | 网页选项示例 |
|---|---|---|
| `0x20` | 50～65 | `PCF8575 0x20 P0` |
| `0x21` | 66～81 | `PCF8575 0x21 P0` |
| `0x22` | 82～97 | `PCF8575 0x22 P0` |
| `0x23` | 98～113 | `PCF8575 0x23 P0` |

将模块设置为不同的上述地址，共用 SDA、SCL 和 GND。在网页的 I2C 配置中选择 SDA/SCL，保存并重启，再按实际接线选择各通道的电机和微动引脚。无需配置芯片数量，可以只接其中任意一片或几片；芯片编号与 AMS 编号不绑定。AHT20、BMP280 继续共用该总线。

状态页分别显示四个地址的检测结果。某片未检测到时，只阻止依赖该片的电机启动和自动微动检测；电机两根控制线跨片时，两片都必须检测成功。未初始化的芯片每 5 秒独立重试，恢复时将输出置低并保留已配置的引脚模式，不重放离线期间缓存的高电平。这里的检测状态表示初始化结果，不是持续热插拔监测。

原有首片 50～65 的配置编号保持不变，设置记录结构、格式标识和 CRC 机制不变，新增引脚同样参与冲突校验和保存回读校验。关闭 I2C 会清空全部四片的扩展接线，未配置电机的通道继续拒绝启动。

本次同时修正了旧代码的高字节位序：P10～P17 对应寄存器位 8～15，不能直接把面板编号 10～17 用作位移。原先针对错误位序调整过实际接线的设备，需要重新核对这组端口。

## 验证

```powershell
python -B tools/tests/test_pcf8575.py --cxx C:/path/to/g++.exe
python -B tools/tests/test_project_presets.py --cxx C:/path/to/g++.exe --json "$env:TEMP/bmcu-projects.json"
node tools/tests/test_web_config.cjs
node tools/tests/test_project_presets_web.cjs "$env:TEMP/bmcu-projects.json"
pio run -e esp32c3
```

主机测试覆盖 64 位寻址、跨片状态隔离、缺片与初始化写失败、重试计时回绕、模式保留、PWM 独立更新、通道就绪判断、接线冲突、设置保存回读和关闭总线后的清理。网页测试覆盖逐地址状态、64 个选项、跨片接线保存与重载、项目预览及手机布局。测试使用硬件桩，实物四片并联和电机运行仍需上板验证。
