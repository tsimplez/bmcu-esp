# 四片 PCF8575 扩展 IO

固件在同一条 I2C 总线上支持最多 4 片 PCF8575，共 64 个扩展引脚。地址固定分配如下，每片的引脚名称均为 P0～P7、P10～P17。

| 芯片地址 | P0～P7 的虚拟编号 | P10～P17 的虚拟编号 | 网页选项示例 |
|---|---|---|---|
| `0x20` | 50～57 | 60～67 | `60（io扩展1 P10）` |
| `0x21` | 70～77 | 80～87 | `80（io扩展2 P10）` |
| `0x22` | 90～97 | 100～107 | `100（io扩展3 P10）` |
| `0x23` | 110～117 | 120～127 | `127（io扩展4 P17）` |

每片有 16 个有效引脚，相邻芯片起始编号相差 20；50～129 范围内尾数为 8、9 的编号无效。代码定义、网页选项值、API 参数和保存记录统一使用这套编号。例如 `60` 对应第 1 片 P10，`70` 对应第 2 片 P0。空缺编号不出现在下拉列表中，也不能通过接线校验或作为真实 GPIO 访问。

将模块设置为不同的上述地址，共用 SDA、SCL 和 GND。在网页的 I2C 配置中选择 SDA/SCL，保存并重启，再按实际接线选择各通道的电机和微动引脚。无需配置芯片数量，可以只接其中任意一片或几片；芯片编号与 AMS 编号不绑定。AHT20、BMP280 继续共用该总线。

状态页分别显示四个地址的检测结果。某片未检测到时，只阻止依赖该片的电机启动和自动微动检测；电机两根控制线跨片时，两片都必须检测成功。未初始化的芯片每 5 秒独立重试，恢复时将输出置低并保留已配置的引脚模式，不重放离线期间缓存的高电平。这里的检测状态表示初始化结果，不是持续热插拔监测。

旧版使用连续的 50～113 编号，与新编号有语义冲突，例如旧 `60` 对应 P12，新 `60` 对应 P10。因此设置格式标识更新为 `0x5341542B`，同时拒绝旧 `0x53415429` 和历史 AMS 版本迁移固件使用过的 `0x5341542A`，不迁移旧记录；升级后旧格式的整份设置恢复平台默认值，需要重新配置。记录结构及 CRC32 算法不变，保存仍需回读校验。关闭 I2C 会清空全部四片的扩展接线，未配置电机的通道继续拒绝启动。

寄存器位序保持 0～15，P10～P17 对应位 8～15；面板名称不能直接用于位移。PWM 缓存用连续的 0～63 索引，不能用含空隙的虚拟编号直接减 50。团子项目预设的微动编号由旧 `60～63` 改为 `62～65`，实体接线仍是 P12～P15。

## 验证

```powershell
python -B tools/tests/test_pcf8575.py --cxx C:/path/to/g++.exe
python -B tools/tests/test_project_presets.py --cxx C:/path/to/g++.exe --json "$env:TEMP/bmcu-projects.json"
node tools/tests/test_web_config.cjs
node tools/tests/test_project_presets_web.cjs "$env:TEMP/bmcu-projects.json"
python -B tools/tests/test_bambu_bus.py --settings
pio run -e esp32c3
```

主机测试覆盖全部 64 个有效编号的寻址、空缺编号拒绝、跨片状态隔离、缺片与初始化写失败、重试计时回绕、模式保留、完整 PWM 周期、通道就绪判断、接线冲突、旧格式恢复默认值、设置保存回读和关闭总线后的清理。设置测试通过 `CXX` 选择编译器。网页测试覆盖逐地址状态、64 个选项、跨片接线保存与重载、四片高低字节边界的项目预览及手机布局。测试使用硬件桩，实物四片并联和电机运行仍需上板验证。
