# 暂停打印实验

顶部“实验测试”标签页提供 **测试暂停**、**解除测试** 两个按钮。点击“测试暂停”后保持 AMS 堵转反馈，目标通道进入“退料中”时自动设为离线，保存成功后解除堵转。离线模式会保留到用户在 Web 中恢复在线或自动，重启也不会恢复。

## 测试步骤

1. 打开顶部“实验测试”标签，等打印进入稳定打印阶段。网页出现“可测试：AMS … · 通道 …”后，点击“测试暂停”。进料准备、空闲、离线模式或通信状态过期时不可触发。
2. 观察打印机暂停和退料过程。固件收到停止供料或“请求退料”时继续保持堵转，只有目标通道进入“退料中”才切为离线。
3. 网页显示“已保存离线并解除堵转”后，检查目标通道的模式已变为离线、退料正常完成，并且没有重新进料。无需再点“解除测试”。
4. 需要恢复使用时，在状态页的“通道参数与手动进退料”中把目标通道改为“在线”或“自动”；沿用现有自动保存。打印机上的错误提示和继续打印仍由用户操作。
5. 回报打印机型号、固件版本、是否暂停、退料后是否又进料、模式恢复结果。主板日志中的 `[pause-test]` 记录触发、停止观察、退料离线和保存结果；完整收发帧可通过 BambuBus 日志采集。

“解除测试”保留为人工解除入口，只解除堵转反馈，不恢复已经切换的离线模式；已登记的离线保存仍会完成。如果尚未进入退料中，人工解除会取消本次自动离线流程。连接失效时仍可提交解除。

保存失败时显示“离线设置保存失败，将自动重试”，保留离线模式和当前堵转反馈，每秒在总线空闲时重试，写入及回读校验通过才自动解除。用户在 Web 中成功恢复通道模式后，后台不再覆盖该选择。

2026-11-04：用户已确认此前持续锁存版本能保持停止到手动解除。本版增加退料中自动离线，尚待用户实机验证。

## 实现与接口

- `BambuBus_request_pause_test()` 只登记请求及当时目标；`BambuBus_run()` 再次检查并执行，HTTP 回调不驱动电机或直接写 UART。
- `pause_test_run()` 在 Cxx/Dxx 状态机处理后、响应构建前观察目标通道。只有目标仍为当前通道且内部状态为 `pull_back`（退料中），才将 `CHANNEL_MODE` 设为 `CHANNEL_MODE_OFFLINE`，同步有料状态并登记保存。`before_pull_back`（请求退料）不会触发。
- `BambuBus_save_run()` 在运动调度完成、总线静默至少 5ms 且冷却到期后，优先通过 `settings_save_to_flash()` 保存现有设置，沿用 CRC 和完整回读校验。成功后才结束堵转反馈，无需改变设置格式。
- `apply_pause_test_response()` 覆盖目标 AMS 所有运动回复的压力 `F06F` 和相邻字 `1CE7`，均为小端，包括无通道轮询和同 AMS 换槽。Cxx 完整帧偏移 13～16，Dxx 为 25～28；其它 AMS 保持正常，沿用长度、序号和 CRC8/CRC16。
- Cxx 准备表的位图由实际在线状态覆盖；Dxx 在线/NFC 位图同样在离线生效后组装，避免恢复正常压力时仍报告目标在线。
- 切换离线不清理运动状态，不直接停止电机。已启动的定时退料保留原截止时间，离线期间的进料重试不能打断；通道微动和五通总微动均不能启动离线通道的自动进料。
- `POST /api/printer/pause-test`，表单 `enable=1` 触发、`enable=0` 解除。202 表示已登记，400 表示参数错误，409 表示没有可用目标或重复触发。
- `GET /api/status` 的 `pause_test` 保留 `available`、`active`、`pending`、`channel`、`candidate_channel`、`frames`、`stop_seen`、`result`。通道使用从 0 开始的全局编号；`pending` 为 1/-1/0，分别表示等待触发/等待解除/无请求。
- `result` 新增 `saving_offline`（等待保存）、`save_failed`（保存失败并重试）、`offline`（已保存离线并解除）和 `restored`（用户已恢复模式）。`stop_seen` 仅表示观察到停止供料，不能据此认定整个打印任务已经暂停。
- `/api/status` 新增 `cm` 通道模式数组，网页轮询同步未编辑的模式下拉框，保留用户正在选择或保存的值。恢复继续使用 `/api/settings` 的 `cmN=1/2`。

## 验证边界

2026-11-04 验证：21 组协议、10 组电机/API、9 组设置存储和 Edge 网页回归通过，`pio run -e esp32c3` 编译通过。没有编译其他板型、烧录或进行本版实机测试。

协议覆盖 Cxx/Dxx 字段及 CRC、停止/请求退料不提前离线、目标隔离、首个退料响应的离线位图、保存期间保持堵转、失败限频重试、成功仅保存一次、手动解除不恢复模式、重启保留模式及人工恢复不被后台覆盖。设置测试单独覆盖真实 CRC、写入和回读失败，协议测试在设置保存接口处使用可控硬件边界。

电机回归运行真实调度及微动处理，验证退料截止时间、离线后的打印机进料重试、两种微动均不重新进料，以及恢复在线/自动后重新进料。网页回归覆盖自动离线同步、等待/失败/完成提示、现有下拉框恢复、失败回滚、草稿保护和手机布局。

这些主机与模拟 HTTP 测试不替代打印机的实际暂停、退料和恢复打印验证。
