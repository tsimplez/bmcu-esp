# BMCU-U 兼容适配记录

日期：2026-10-25。固件版本：`26.10.25`。本文件记录本项目的实现和验证；可复用的协议字段仍独立保存在 [BambuBus协议分析.md](BambuBus协议分析.md)，适配前的比较见 [BambuBus项目差异与兼容性调查.md](BambuBus项目差异与兼容性调查.md)。

## 1. 参考与适用范围

主要参考 BMCU-U 提交 `2ea0963d978d19239a987974db2d08acb09e3656`。2026-10-25 用 `git ls-remote origin refs/heads/main` 复核，上游 main 仍指向该提交。

BMCU-U README 明确声称测试通过的是 A1/A1 mini 打印机固件 **01.08.01.00**。本次完成该实现中相关协议行为的迁移，没有连接真实打印机；不能据此承诺任意后续固件都兼容，也没有实现 `040D/040E` 认证。

## 2. 已实施的修改

| 位置 | 修改 | 目的 |
|---|---|---|
| BambuBus_init | 波特率从 1,228,800 改为 1,250,000，保留 8E1 | 与 U 的总线参数一致 |
| get_package_type | 接受长帧请求 flags 04 和 05 | 避免忽略 U 已支持的另一类请求；保留长度、CRC、地址和通道校验 |
| send_for_Fxx / registration_identity_matches | 各 AMS 首次报名 0C，后续 0A；确认匹配 0A 和 16 字节身份 | 对齐注册阶段，保留每 AMS 注册保持和本项目统一序列号 |
| process_motion_state_machine | 增加 09/7F；修正 09/A5 首次及重复反馈 | 按请求和历史区分准备流程 |
| set_prepare_response / bambu_motion_reference.h | Cxx 回放 U 保存的全部 45 行数据 | 对齐压力、未知区和末尾字节，结束后恢复基础模板 |
| 使用反馈 | 7F 准备后前 5 次进入使用反馈 1E34，之后 2B00 | 保留连续报文中的阶段变化 |
| 送出转使用 | 15 秒等待；等待时动作仍为送出，但回复 04/2B00 | 将电机动作和协议反馈分开 |
| 无通道请求 | FF/01 不清除正在使用或回抽的通道；本地完成后才释放选择 | 避免打印轮询误中止活动通道 |
| 停止与回抽 | 07/00 可停止送出；FF/03/00 可从准备、使用、暂停或退料准备进入回抽 | 对齐 U 的停止及回抽入口 |
| BMCU_motion | 明确停止供料时跳过常规一秒延迟，主循环执行 motorCmd 停车 | 协议处理不直接驱动电机，停料及时生效 |
| Cxx / Dxx 回复 | 每帧重新初始化 U 模板；空闲米数 0、压力 FF74；Cxx 空闲相邻字段 0008；Dxx F[12] 回显请求通道 | 避免特殊序列污染普通帧，同时对齐固定未知区和通道字段 |
| 设置与网页 | 默认 AMS08 版本 1.0.6.87，线上 57 06 00 01 | 对齐 U 的版本声明，并迁移旧默认值 |

特殊 Cxx 序列有一个已知偏移歧义：U 实际把两个 32 位值写到 F[29..32] 和 F[33..36]，与普通结构体边界不同。本次保留实际输出位置，并通过完整帧测试锁定行为；没有将这些未知字节解释成已确认的传感器字段。

准备计数、等待时间和反馈历史按 AMS/通道保存。Dxx、其他 AMS 的轮询、无效 CRC 和发送忙不推进当前通道的 Cxx 准备序列。现有 4/8/12/16 通道支持、温湿度采样、NFC 状态、计米与电机互锁继续使用本项目实现。

未迁移依赖 U 专用机械结构/传感器的堵转判定，不伪造 F06F 堵转状态。通信超时保护和本地定时退料仍使用本项目既有规则，U 的本地超时常量没有被解释为打印机的协议硬时限。

## 3. 旧配置迁移

设置布局保持不变。记录标记由 `0x53415429` 更新为 `0x5341542A`：

1. 旧标记与完整 CRC32 正确时加载记录，沿用现有参数及接线校验。
2. AMS 版本恰好为旧默认 `90.0.0.0` 时改为 `1.0.6.87`，其他自定义版本保留。
3. 通过现有保存函数写入新标记和 CRC，并完整回读比较。失败恢复旧运行参数并记录日志。
4. 已迁移记录不重复写入，之后主动改回 `90.0.0.0` 也不会在每次启动时被覆盖。

只迁移上一版相同布局的记录。更早的未知格式或 CRC 损坏记录仍遵循原有恢复默认策略。旧格式不能区分“未改过默认值”与“用户主动设成相同的 90.0.0.0”，二者都会迁移。

新标记不能被未包含迁移逻辑的旧固件识别。若计划回刷旧固件，应先记录接线、通道等设置，否则旧固件可能按自己的策略恢复默认值。

升级后检查网页中的固件版本和 AMS 版本。此前自定义的 AMS 版本会保留；要复现 U 的这组行为，应将其设为 `1.0.6.87`，再让打印机重新枚举设备，以实际 `0103` 回复为准。

## 5. 实机验证重点

依次检查开机发现、首次进料、打印准备、稳定打印、暂停恢复、换色、取消、第一任务结束后的第二次打印；多 AMS 配置再检查跨 AMS 换色。

- 记录打印机型号、准确固件号、AMS 版本设置、任务阶段及 HMS 错误码。
- 检查 09/7F 是否出现、45 帧准备输出是否完整、随后 07/7F 的压力变化和应答间隔。
- 检查打印中 FF/01 是否保持当前通道、07/00 后电机是否及时停料。
- 保留停印前后的双向原始帧，包含未知命令、CRC 错误和丢帧统计，并记录 Web/OTA 或 Flash 保存是否发生。

若仍有认证提示或停印，应据日志区分版本/身份检查、额外认证命令、回复时序和机械供料问题。软件测试证明已列输入下的实现行为，尚不能证明用户所述停印问题已在实机消失。
