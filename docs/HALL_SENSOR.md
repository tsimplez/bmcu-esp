# 49E 霍尔采样与通道卡片

每个启用通道都可配置一个 49E 线性霍尔的模拟输出引脚，默认是「无」。当前功能用于查看原始 ADC 读数和最近一分钟的变化，不参与电机控制、堵转判断或 BambuBus 压力反馈。

## 接线与可用输入

在网页「设置」的通道引脚区选择「霍尔 ADC」，与 AMS 数量、电机和微动引脚一起保存。保存成功后由主循环应用，失败时回滚完整设置。霍尔不能与电机、微动、五通总微动、BambuBus、I2C 或另一个霍尔共用引脚；PCF8575 没有模拟输入能力，不能用于此项。

| 平台 | 固件支持的模拟输入 | 进一步限制 |
|---|---|---|
| ESP32-C3 / 合宙 C3 | ADC1：GPIO0～4 | GPIO5 不参与霍尔采样；GPIO2 保留启动绑带提示 |
| ESP32-S3 | ADC1：GPIO1～10 | 已被接线占用的输入必须先释放 |
| RP2040 | GPIO26～29 | 仍受板级引出和原有接线限制；没有网页界面 |

可选列表会过滤系统保留、总线和 I2C 引脚，并显示其他通道的占用情况。逻辑通道最多十六个，不代表主控有十六个独立 ADC 输入。当前 C3 四色四微动默认预设占用 GPIO0～4；团子八色预设使用 GPIO4/5 做 I2C，通常只剩 GPIO0～3 可选。新增霍尔前需按实际硬件调整接线。

49E 的电源范围、引脚顺序和输出幅度应以实际厂家资料为准，传感器与 ESP32 共地，模拟输出接选定的 ADC 输入。本固件使用十二位 ADC 与最高衰减，C3 的有效测量范围不覆盖整个 3.3V 电源范围；输出超过约 2.5V 时需按实际电路缩放，不能将 5V 模拟输出直接接入主控。原始读数不是磁场、力或张力的物理单位，也不能据此可靠判断模拟传感器是否拔掉。

ADC 配置依据 Espressif 的 Arduino ADC 文档；平台实现位于 `src/platform.cpp` 的 `hal_adc_pin_available()`、`hal_adc_prepare()`、`hal_adc_read()`。Arduino 3.3 的逐引脚衰减接口不能配置尚未初始化的模拟通道，因此在准备采样时设置全局默认衰减，实际转换仍按主循环节拍执行。

## 卡片与数据含义

- 通道按 AMS 分组，电脑端两列、手机端一列，保留模式、退料超时、手动进退料、停止和排队操作。
- 未配置霍尔的通道隐藏整个霍尔读数、曲线和统计区；保存有效 ADC 引脚后显示，关闭后再次隐藏。
- 通道在线或自动模式有料时，整张卡片显示绿色边框和浅绿背景；自动模式无料时显示蓝色边框和浅蓝背景。颜色依据设备返回的通道模式与微动状态，离线或状态未知时使用普通底色。
- 打印机明确正在使用的通道仅在「当前使用」标签上显示紫色背景。进料、退料和选中状态分别标注，未选中时隐藏标签；手动电机运行不触发此标签高亮。
- 打印机状态由 `BambuBus_current_channel_status()` 提供，要求心跳、总线报文和本通道运动状态有效；通道停用、离线、通信失效或运动状态过期后取消「当前使用」高亮。网页状态请求失败或响应过期时，清除卡片颜色和标签高亮，并显示「状态待确认」。
- 每通道目标采样频率为 20Hz，每个主循环最多执行一次 ADC 转换；忙碌造成的漏采样不集中补读。
- 每 200ms 保存一个平均值、最小值和最大值，最多保留 300 桶。折线表示桶平均值，阴影表示最小至最大范围；缺失采样保留断点。
- 卡片显示当前值，以及六十秒内有效完整桶的最小、最大和平均值。分钟平均值为桶平均值的等权平均；未完成桶不计入分钟统计。
- 最近读数超过 500ms 失效；网页请求失败或响应过期后不继续显示旧值为当前值。原始 ADC 的零是合法读数，缺失值使用 `null`。
- 历史保存在 RAM，网页关闭期间仍采样；重启、有效霍尔接线或 AMS 数量变化时清空历史。C3 只预留五份 ADC 历史槽，不按十六个逻辑通道分配。

## 接口与分页

`GET /api/settings` 在 `io` 对象内增加 `hall[16]` 与 `hall_pins`。引脚选项沿用 `id`、`label`、`warning`、`warning_text`。`POST /api/settings` 使用 `io_h0`～`io_h15`：一旦提交霍尔字段，须完整提交全部启用通道的霍尔与原有通道引脚；完全不带霍尔字段的旧表单保留当前霍尔配置。项目预览的 `pins` 行增加第四列霍尔引脚。

`GET /api/status` 增加 `current_channel`（0～15 或 -1）与 `current_channel_state`（`using`、`feeding`、`retracting`、`selected`、`none`）。这些字段只用于展示，不改变协议反馈。

第一次使用 `GET /api/hall`，之后使用上次响应的 `epoch`、`cursor`：

```text
/api/hall?epoch=123&cursor=50
```

响应包含：

| 字段 | 含义 |
|---|---|
| `epoch` | 本次启动与接线版本的非零标识 |
| `cursor` | 本次最后交付的完整桶游标 |
| `reset` | 页面应丢弃旧历史，从本页开始合并 |
| `more` | 仍有后续历史，需要继续使用本页游标读取 |
| `interval_ms` | 200ms |
| `now_ms` | 设备当前无符号毫秒时刻 |
| `channels` | 全部启用通道，含未配置通道 |
| `channels[].channel / pin` | 零起点通道编号、实际运行期引脚（255 表示未配置） |
| `channels[].raw / min / max / avg` | 当前原始值、分钟统计；没有数据时为 `null` |
| `channels[].points` | 按时间从旧到新的 `[age_ms, average, minimum, maximum]`；`age_ms` 相对本次 `now_ms` |

每页最多 50 桶，初次或重置后从现存最旧数据开始读取，避免一次分配完整一分钟的 JSON。未配置通道的 `points` 为空。游标超过保留窗口、来自未来或版本不匹配时重置；非法、溢出或缺一项的查询参数返回 400。接口只读缓存，不在 HTTP 回调中采样。浏览器每秒增量更新，补历史时逐页请求，离开状态页或隐藏页面时暂停请求。

## 设置格式与验证边界

加入 `IoConfig.hall` 后设置格式为 `0x5341542E`。旧格式（包括 `0x5341542D`）按项目规则恢复整份默认设置，不做迁移；升级前记录当前项目、接线、身份和参数，升级后重新配置。设置仍执行 CRC、写入回读验证与失败回滚。

主机采样和接口回归入口为 `tools/tests/test_hall_sensor.py`；接线与保存由项目/API 回归覆盖，卡片和曲线由 Edge 网页回归覆盖，命令见 `tools/README.md`。主机测试不能验证实际 49E 噪声、量程、电气接线、模拟输入精度或连续打印时的总线响应；这些需要实机验证。
