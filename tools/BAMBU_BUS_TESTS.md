# BambuBus 回归测试

`test_bambu_bus.py` 将真实的 `src/BambuBus.cpp`、协议声明、平台原子接口和 `src/crc_bus.c` 编入主机测试
只替换串口、时钟、存储等硬件边界，不复制或改写协议算法编译产物放在系统临时目录

有 GCC/Clang 时运行：

```powershell
python tools/test_bambu_bus.py
# 或通过 CXX 指定编译器；Zig 可使用 --zig C:\path\to\zig.exe
```

在禁止运行新生成本机程序的环境中，可使用 Zig 0.15.2 或更新版本和 Node.js 执行 WebAssembly 沙箱测试：

```powershell
python tools/test_bambu_bus.py --zig C:\path\to\zig.exe --wasi
```

WASI 不开放文件目录，运行十四组功能测试，明确跳过仅本机支持的 `queue_threads` 并发压测

覆盖范围：

- 命令最小载荷、帧长、CRC8/CRC16、AMS/通道、地址与回显过滤
- 队列顺序、满队列丢新帧、处理期间持有缓冲、队列序号回绕
- 残帧超时恢复、回调忙状态、长包双字节长度
- 启动无通信、错误帧不续期、超时锁存和时间回绕
- 保存前队列/UART/回调/残帧/收发静默检查，一秒冷却，写入或回读失败重试
- 零毫秒计时起点、注册查询身份长度及实际回复的长度与 CRC
- 全部 4 个 AMS × 4 个通道的 Cxx、Dxx 和交替运动序列：送出、准备、使用、停止、退料和空闲
- 重复准备请求、当前通道反馈，以及非当前通道请求不改变使用中的通道
- 其他 AMS 的无通道请求不清除当前通道、等待起点或打印机阻断；真实换料仍释放旧通道
- 5 秒等待的零起点与回绕边界、内部停车后重新计时、交替报文不重复累计长度及累计上限
- 发送槽占用时保留请求且不改变运动或耗材设置，仍处理通信超时，释放后再处理队首
- RX 日志、UART 写入、TX 日志期间重入不消费下一帧，修改源模板不改变在途数据及日志关联
- 注册身份的 17 个字节逐个篡改均不确认，错误身份不刷新通信状态、不取消已有注册
- 4 个 AMS 的注册身份各不相同，注册包与序列号载荷一致；查询顺序、自定义序列号和恢复自动值不产生旧数据

第二批的字段约定：Cxx 请求的通道/运动标志为 `[7]/[8]`，Dxx 为 `[9]/[7]`
两种请求共用状态处理和反馈生成，反馈采用本 AMS 当前活动通道，无通道查询仍正常回复
`09/A5` 准备阶段固定反馈 `0x2B00`，重复准备请求保持使用中压力；进入使用后反馈 `0x2B00`
保留原有 5 秒等待与空闲压力 `0xFFFF`，未引入 PJARCZAK 的 `09/7F` 特殊序列或 15 秒等待

发送预占和身份统一的约定：

- 保留平台同步 UART 发送，复用原有 1000 字节缓冲；单次请求预占持续到全部回复和日志结束
- 注册包 `[8..23]` 与同一 AMS 序列号载荷 `[33..48]` 完全一致，另检查原有的身份前缀 `[7]`
- 普通查询保留各 AMS 注册状态，错误身份既不发送确认也不取消已建立的注册
- 自定义序列号仍完整使用配置的 15 字符；二进制身份由芯片 ID 和 AMS 编号区分，配置变化后重新注册
- 未改为异步或分步发送，未增加自动地址分配、新注册前缀和重排命令

实机复核重点：分别检查 Cxx/Dxx 进退料、准备阶段压力反馈、无通道查询和多 AMS 轮询
第一批的用户实机反馈不代表这些第二批行为已经经过实机验证
身份统一后的实机复核还需覆盖重新发现 AMS、注册确认、序列号查询与断线重连；旧版固定注册身份已改为芯片 ID 身份

固件只编译 `pio run -e esp32c3`，这些测试不能替代 RS485 实际时序、连续打印和断线重连的实机验证
后台保存仅检查开始写入之前的总线状态；无法保证写入期间没有新报文到达
